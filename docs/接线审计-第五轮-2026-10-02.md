# 接线审计（第五轮）2026-10-02

## 方法

对 `core/` 下全部框架类，逐个公开方法检查**主代码中是否存在调用方**。

审计脚本判定标准：方法名在整个 `app/src/main/java` 中
（除自身定义外）出现次数 ≤ 1 次 → 判定为「无调用方」。

**为什么做这个审计**
本轮已发现 `TextDiffEngine` + `NodeTextMonitor` 写完但从未接线 ——
这类失效单测查不出来（引擎测试全绿），必须专门审计「接线」。

## 已修复（1 项，本轮）

### ✅ 增量朗读引擎从未接线

- `TextDiffEngine`（文本差分）与 `NodeTextMonitor` 从创建起无任何调用方
- 文本变化事件 (2048) 走的是**整段重读**
- `AccessibilityEventHandler` 类注释甚至已写「2048 文本变化 → 增量播报」，
  但代码里没有 —— **注释与实现不符**
- 后果：聊天/股票/弹幕类界面文本一变就整段重念，噪音淹没用户
- 已修复并补 `TextDiffWiringTest`

**顺带修复**：`NodeTextMonitor.onTextChanged` 参数原为不可空，
而 `event.source` 可空 —— 真机遇到无 source 的文本变化事件会崩。
读屏是常驻服务，崩溃等于用户彻底失去辅助。

## 待确认（未改动，需产品决策）

### ⚠️ 输入法适配 API 无调用方

服务里存在完整的输入法适配能力，但**没有任何调用方**：

| 方法 | 用途 |
|---|---|
| `speakFromIme(text, queueMode)` | 输入法请求播报候选词 |
| `interruptSpeech()` | 输入法请求打断播报 |
| `activateNodeByTexts(texts)` | 候选词上屏 —— 按文本找可点击祖先并点击 |
| `onImeTouchExplorationChanged(disable)` | 接输入法时切换触摸探索 |

而 `ImeWindowDetector.isInputWindowOnScreen()` **是**被调用的
（用于触摸探索的输入法窗口判定）。

**判断**：这不是 bug，而是**未完成的功能面**。
`onImeTouchExplorationChanged` 需要 `serviceInfo.flags` 层面配合，
且 `activateNodeByTexts` 的「按文本找祖先」是针对特定输入法的适配策略，
在不知道目标输入法的情况下贸然接线会造成误点击。

**建议**：保留现状 + 保留注释。接线需要先确定目标输入法。

### ⚠️ `reloadReplacementRules()` 无调用方

- 规则在服务启动时加载（`loadWithBuiltin`）
- 但用户改规则后**没有重载路径**
- 原因：目前**没有规则编辑界面**（`ui/` 只有 MainActivity 与 TtsSettingsActivity）
- 判断：这是「编辑界面」缺位导致的连带现象，不是接线遗漏
- 建议：做编辑界面时一并接线；方法本身正确

## 保留（确认无问题）

### 纯函数工具（19 个）
`Bounds.intersects/unionWith/...`、`TraversalDirection.toLogical/...`、
`GranularityMover.extractTraversedText` 等 ——
这些被**测试**直接调用，且是几何/方向判定的公共工具。
保留。

### 调试/统计（8 个）
`TraversalStrategy.cachedSize()`、`NodeBoundsCalculator.cacheSize()`、
`WindowTraversal.windowCount()/describeWindows()` 等 ——
性能审计用。保留。

### 冗余别名（建议清理，低优先级）

| 方法 | 问题 |
|---|---|
| `SpeechCompositor.describe()` | 就是 `compose()` 的别名，无额外语义 |
| `SpeechEngine.speakInterrupt()` | 就是 `speak(interrupt=true)` 的别名 |

两者都是「便利包装」，保留不会出错，但会让人误以为有独立行为。
**建议**：下次重构时删除，避免调用方误用。

## 结论

- 修复 1 项真实失效（增量朗读）+ 1 项崩溃风险（空安全）
- 24 项「需人工判断」中：22 项经核实为**未完成功能面**或**测试工具**
- 无其他「代码在、功能不在」的失效

> 「写完没接线」这类问题。
