## 三、本轮新补齐的两项能力

### ✅ 输入法适配（对照天坦 `X6/k`）

**天坦做法**（X6/k.java:214~236）——显式双路径：
```java
if (SDK_INT >= 33) {
    InputMethod.AccessibilityInputConnection conn =
        service.getInputMethod()?.getCurrentInputConnection();
    if (conn != null) conn.commitText(str, 1, null);
} else {
    F0.p(service, str, false, 2, null);       // 旧路径
    postDelayed(300ms) { 清理节点 };
}
```

**TalkBack 做法** —— 全仓库 grep 无
`AccessibilityInputConnection` 使用，**未实现此路径**。

**抉择**：TalkBack 无对应实现，无取舍问题，直接照天坦。

**实现**：`ImeTextCommitter` + `ImeAdapter`，相对天坦改进：
天坦只有「成功 / 静默失败」两条路，调用方拿不到结果。
改为三级降级链，每级明确返回成败：
1. `InputMethod.commitText()` — 官方接口（API 33+）
2. 按文本找可点击祖先 click — 覆盖自绘候选词输入法
3. 返回 null → 调用方播报失败提示

第 3 级是关键：**读屏里静默失败比失败本身更糟**。

同时把上一轮记录的 4 个无调用方 IME 方法收进 `ImeAdapter` 并接线。

### ✅ 导航标签网页二分（对照天坦 `X6/z.b.f()`）

**天坦做法**：只有 链接/控件/标题 三种导航有网页专用标签
（`granularity_native_link` ↔ `granularity_web_link`）。
原因：网页里的「链接」走 HTML 语义跳转，行为与原生不同，
用户听到「链接」无法判断当前是哪种模式。

**TalkBack 做法**：用独立枚举项区分
（`HEADING` 与 `WEB_LIST`/`H1~H6` 并列），
在 `getSupportedGranularities()` 里按 `hasWebContent` 动态过滤。

**抉择：选天坦** ——
TalkBack 要求把粒度表翻倍 + 动态计算可用集合，
对白茶现有的单层 `GranularityNavigator` 是伤筋动骨的改造；
天坦只改标签文案，不动结构，用户收益相同。

**实现**：`NavigationLabel`，切换导航时按当前节点是否支持
HTML 动作决定念「链接」还是「网页链接」。

### ✅ 滚动去重键核对

天坦 `M6/r.b` 用 `(node.hashCode(), windowId)` 作 `NodeIdentifier`。
白茶 `AccessibilityEventHandler` 用 `(lastScrollNodeKey, lastScrollWindowId)`
—— **一致**，无需改动。
