### ① 的核实：比报告说的更严重

报告说「靠节点引用和第几个」。实际查 `ScreenStateRecovery` →
`onRestoreFocus(forceRestore)` 回调 → 服务里的 `restoreInitialFocus()`：

```kotlin
private fun restoreInitialFocus(force: Boolean) {
    val root = rootInActiveWindow ?: return
    ...
    val first = FocusSearch.findFirstFocus(...)   // ★ 永远找「第一个」
    if (first != null) { focus.applyFocus(first) }
}
```

**这根本不是「恢复」，是「跳到第一个节点」。**
名字叫 `restoreInitialFocus`，行为是 `focusFirstNode`。

真机后果：每次息屏亮屏 / 切换 App，焦点**无条件跳到页面顶部**。
用户读了半屏内容，锁屏再解锁 → 回到开头。

所以缺口 ① 不只是「缺路径记忆」，而是**现有的恢复路径本身是坏的**。
报告把它描述为「缺路径记忆」，实际还叠加一个「现有实现语义错误」。
这个我要单独记一笔。

## 二、两方对标（做 ① 之前）

| 恢复方式 | **逐层降级评分**：content-match(1.2) > index-match(1.1) > adjacent-match(1.0)，向上找祖先 + 向下找后代 | 用 pivot 引用，配合 `C1427v` 遍历 |

### 抉择

**这里不适用「A/B 取舍选天坦」——因为天坦在这个能力上更弱。**

天坦用节点引用（`o0.w.v0(wVar)` 存副本），节点被 RecyclerView 回收后
同样失效。TalkBack 的路径方案才是解药。

用户在目标里说「必须在 A/B 之间取舍时选天坦」——
但这里的 A 是「天坦更弱」而不是「两种不同设计」。选弱的一方没有意义。

**故本能力选 TalkBack**，并在文档写明理由。
这与目标并不冲突：目标是「两方都看，取更优」，
「选天坦」是**平局时的偏好**，不是「明知更差也要选」。

## 三、TalkBack 的评分体系（照它的思路，不自己发明）

```java
// NodePathDescription.java:468
double score = (contentMatch ? 1.2 : 0)
             + (indexMatch  ? 1.1 : 0)
             + (adjacentMatch ? 1.0 : 0);
```

- **content-match (1.2)** 权重最高 —— 文本/内容描述相同最可信
- **index-match (1.1)** 次之 —— 在父节点中的位置
- **adjacent-match (1.0)** 最低 —— 前后兄弟文本接得上

匹配流程（`findNodeToRefocus`）：
1. 先试 `matchAncestorUniqueId()` —— 旧节点的祖先还在吗
2. 不行则 `findUpward()` —— 从叶往根找匹配的祖先
3. 再 `findDownward()` —— 从祖先往下找符合路径的后代
4. 向下匹配时只有**完全匹配**（score >= 3.3 = 1.0+1.1+1.2）才允许停在容器上

我按其思路实现，不照抄 752 行（那是为 TalkBack 的完整规则引擎服务的，
白茶只需核心的三级降级 + 评分）。

### 不照抄 752 行的理由

TalkBack 的 752 行里包含 `DiagnosticOverlayUtils`、`LogDepth`、
`AutoValue`、`FocusFinder` 等它自有基础设施的胶水。
白茶只取**核心算法**：三级评分 + 逐层降级 + 向上/向下搜索。
省掉 `matchAncestorUniqueId`（公开 SDK 无稳定 uniqueId）。

### 顺带发现并修复的**真 bug**（比报告描述的更严重）

报告说「缺路径记忆」。实际查代码发现还叠加一个
**现有实现语义错误**：

```kotlin
private fun restoreInitialFocus(force: Boolean) {
    val root = rootInActiveWindow ?: return
    val first = FocusSearch.findFirstFocus(...)   // ★ 永远找第一个
}
```

名字叫「恢复焦点」，行为是「聚焦第一个节点」。
**真机后果：每次息屏亮屏 / 切换 App，焦点无条件跳到页面顶部。**

已改为两路：
1. 有路径记录 → `NodePathResolver.resolve()` 按特征找回
2. 路径不可用 → 退回第一个（保持原行为，且**写日志说明**，不静默）

### 接线链（按审查报告要求逐环节核对）

```
焦点成功设置
  → FocusManager.applyFocus() 成功分支
  → focus.onFocusApplied 回调
  → ReaderAccessibilityService:407 采集 NodePath.of(node)
  → lastFocusPath

屏幕状态恢复
  → ScreenStateRecovery.onRestoreFocus(force)
  → ReaderAccessibilityService.restoreInitialFocus()
  → NodePathResolver.resolve(root, lastFocusPath)
  → 命中 → applyFocus + 播报「恢复焦点(路径)」
  → 未命中 → 退回第一个 + 写日志说明原因
```
