## 一、缺口 ①：焦点路径记忆（NodePathDescription 等价物）

### 两方怎么做

| | 文件 | 行数 |
|---|---|---|
| TalkBack | `focusmanagement/record/NodePathDescription.java` | **752** |
| TalkBack | `focusmanagement/record/NodeDescription.java` | 320 |
| 天坦 | `w7/AbstractC3693m` 里的节点路径重建 | — |
| **白茶** | **无** | **0** |

### TalkBack 的核心思路

**不靠「第几个节点」找焦点，靠「节点路径」。**

```java
// NodePathDescription.java（TalkBack）
// 从根到叶的完整路径，每层记录：
//   ① 该层在父节点中的 index
//   ② 节点的角色（role）
//   ③ 文本特征（text / contentDescription 的 hash）
// 恢复时逐层下钻，某一层对不上就用「角色 + 文本」模糊匹配
```

**关键：路径匹配是「逐层降级」的 —— index 对不上就比角色，角色对不上就比文本。**

### 白茶现状

```kotlin
// ScreenStateRecovery.kt（279 行）
// 恢复方式：记住「上次焦点的节点引用」或「第几个可聚焦节点」
// ScrollFocusRecovery.kt（174 行）
// 恢复方式：记住「滚动前的 pivot 节点」
```

**问题**：节点被回收（RecyclerView 复用）后，`node` 引用失效；「第几个」在列表重排后错位。

### 真机表现

- 列表滚动后焦点跳到**相邻项**而不是原项
- 弹窗关闭后焦点回到**错误位置**
- 页面刷新后焦点**丢失**（因为 index 变了）

### 建议实现

```kotlin
/**
 * 节点路径描述 —— 对标 TalkBack NodePathDescription
 *
 * 用途：焦点恢复时，不靠节点引用（会被回收），
 *       不靠 index（会被重排），靠「从根到叶的路径特征」。
 */
data class NodePath(
    val segments: List<PathSegment>
) {
    data class PathSegment(
        /** 在父节点中的 index */
        val index: Int,
        /** 节点角色（按钮/列表项/文本…） */
        val role: NodeRole,
        /** 文本指纹（text + contentDescription 的稳定 hash） */
        val textFingerprint: Int,
    )

    companion object {
        /** 从节点向上走到根，收集路径 */
        fun of(node: AccessibilityNodeInfo): NodePath? { ... }
    }
}

object NodePathResolver {
    /**
     * 按路径找回节点 —— 逐层降级匹配
     * ① index 精确匹配
     * ② index 失败 → 同层找 role 相同的
     * ③ role 也失败 → 同层找 textFingerprint 相同的
     */
    fun resolve(root: AccessibilityNodeInfo, path: NodePath): AccessibilityNodeInfo? { ... }
}
```

**接线点**：`ScreenStateRecovery` / `ScrollFocusRecovery` 恢复焦点时，先试 `NodePathResolver.resolve()`，失败再退回现有的引用方式。

## 二、缺口 ②：手势映射可配置（GestureShortcutMapping 等价物）

### 两方怎么做

| | 文件 | 行数 |
|---|---|---|
| TalkBack | `gesture/GestureShortcutMapping.java` | **1264** |
| TalkBack | `gesture/GestureController.java` | 997 |

| 天坦 | `ui/settings/TouchControlPreferencesActivity` | 触摸控制偏好界面 |
| **白茶** | `Gestures.kt` 里 **46 条硬编码** | **316** |

### TalkBack 的 1264 行里有什么

1. **多指手势识别**（1~5 指的各种组合）
2. **手势冲突检测**（同一手势被分配两次 → 提示）
3. **手势变更通知**（`GestureChangeNotificationActivity`）
4. **导入/导出**（用户配置可迁移）
5. **手势历史**（`GestureHistory` —— 记录最近手势，用于「重复手势」识别）

### 白茶现状

```kotlin
// Gestures.kt:228
object GestureMap {
    // 46 条硬编码映射
    // 用户不能改，不能加，不能删
}
```

### 真机表现

- 用户习惯了 TalkBack 的手势 → 用白茶**改不了**
- 某个手势和输入法/系统冲突 → **没法换**
- 换手机后手势配置**带不过去**

### 建议实现

**不要一次抄 1264 行，先做最小可用版：**

```kotlin
/**
 * 手势配置存储 —— 对标 TalkBack GestureShortcutMapping 的持久化部分
 */
object GestureStore {
    /** 默认映射（现有 46 条） */
    private val defaults: Map<GestureId, GestureAction> = ...

    /** 用户覆盖 */
    private var overrides: Map<GestureId, GestureAction> = ...

    fun resolve(id: GestureId): GestureAction =
        overrides[id] ?: defaults[id] ?: GestureAction.NONE

    /** 冲突检测：同手势被分配两次 */
    fun detectConflicts(): List<GestureId>

    fun save(context: Context) { ... }
    fun load(context: Context) { ... }
}
```

**第二期再补**：多指手势、手势历史、导入导出。

**接线点**：`GestureMap` 改成查 `GestureStore.resolve()`。

## 三、缺口 ③：焦点动作历史（AccessibilityFocusActionHistory 等价物）

### 两方怎么做

| | 文件 | 行数 |
|---|---|---|
| TalkBack | `record/AccessibilityFocusActionHistory.java` | **445** |
| TalkBack | `record/FocusActionRecord.java` | 262 |
| TalkBack | `record/FocusActionInfo.java` | 293 |
| **白茶** | `FocusMonitor.kt` 里 **1 个字段** | **247** |

### TalkBack 的 ActionHistory 提供什么

```java
// AccessibilityFocusActionHistory.java（TalkBack）
// ① 完整历史：最近 N 次焦点动作（谁移的、移到哪、什么类型）
// ② getLastEditableFocusActionRecord()  ← 白茶抄了这个
// ③ getLastFocusActionRecord()          ← 白茶没有
// ④ getLastFocusActionRecordInWindow()  ← 白茶没有
// ⑤ 判断「这次焦点变化是不是我造成的」  ← 白茶没有（竞态判定靠别的）
```

### 真机表现

- 焦点乱跳时**无法追溯**「是谁移的」（用户操作？App？系统？）
- 想「回到上一个焦点」→ **做不到**
- 多窗口场景下「这个窗口上次焦点在哪」→ **不知道**

### 建议实现

```kotlin
/**
 * 焦点动作历史 —— 对标 TalkBack AccessibilityFocusActionHistory
 */
data class FocusActionRecord(
    val nodePath: NodePath,          // 缺口① 的产物
    val windowId: Int,
    val actionType: FocusActionType, // USER_NAV / APP_REQUEST / SYSTEM / RESTORE
    val timestamp: Long,
    val role: NodeRole,
    val isEditable: Boolean,
)

class FocusActionHistory(private val maxSize: Int = 20) {
    private val records = ArrayDeque<FocusActionRecord>()

    fun record(r: FocusActionRecord) { ... }

    /** 最近一次焦点动作 */
    fun last(): FocusActionRecord?

    /** 最近一次可编辑焦点（白茶已有，保留） */
    fun lastEditable(): FocusActionRecord?

    /** 指定窗口内最近一次 */
    fun lastInWindow(windowId: Int): FocusActionRecord?

    /** 判断某次焦点变化是否由我们发起（竞态判定用） */
    fun isOurs(node: AccessibilityNodeInfo, windowId: Int): Boolean
}
```

**接线点**：
- `FocusManager` 每次成功移动焦点后 `history.record(...)`
- `ScreenStateRecovery` 恢复时优先查 `history.lastInWindow()`
- 新增手势：`FOCUS_BACK`（回到上一个焦点）—— 天坦和 TalkBack 都有

## 四、缺口之间的依赖关系

**这三个缺口不是独立的，有依赖顺序：**

```
① NodePath（路径记忆）
   ↓ 被依赖
③ ActionHistory（动作历史）—— 每条记录里存 NodePath
   ↓ 被依赖
② GestureStore（手势配置）—— 「回到上一个焦点」是个手势
```

**建议顺序：① → ③ → ②**

**如果只做一个，做 ①** —— 它是另外两个的基础，也是「焦点跳错位置」的直接解药。
