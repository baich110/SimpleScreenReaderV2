# 静默失效审计（2026-10-02 第十二轮）

> 方法：扫描所有公开方法，找出「实现了但从未被调用」的。
> 这类问题不报编译错、不崩溃，**功能看起来在，实际没生效** —— 最难发现。

## 修复 1：朗读替换引擎从未加载规则（P0）

### 症状

`ReadReplacementEngine` 实现了完整的替换逻辑（两级作用域 + 正则 + 捕获组），
但：

```kotlin
var enabled: Boolean = false          // 默认关闭
// 全项目搜索 setRules() 的调用 → 0 处
```

**结论：整个朗读替换功能静默失效。** 用户配了规则也不会生效。

### 为什么审计才发现

- 代码本身没有错误（逻辑正确、编译通过）
- 单元测试也测不到（测的是引擎逻辑，不是"是否被使用"）
- 只有「扫描调用点」才能发现

### 修复

新增 `ReadReplacementStore.kt`（211 行）—— 补上存储层：

| 能力 | 说明 |
|---|---|
| `loadInto()` | 加载规则到引擎（含启用状态）|
| `save()` / `addRule()` / `removeRule()` | 规则增删 |
| `builtinRules()` | 内置规则（网址简化、星号清理等）|
| `loadWithBuiltin()` | 内置 + 用户规则合并加载 |
| JSON 存储 | 而非 StringSet（避免分隔符误伤正则）|
| 容错 | 单条规则解析失败不影响其余 |

服务启动时加载，并新增 `reloadReplacementRules()` 供设置界面热重载。

## 修复 2：滚动状态机的隐式依赖（P1）

### 症状

```kotlin
isScrolling = true          // onScrollStart 调用（服务里有）
isScrolling = false         // onScrollEnd —— 全项目 0 处调用
```

`isScrolling` 置 true 后**无法显式清除**，只有三条路径：
1. 反方向导航时清除（需要 TTL 未过期）
2. 窗口变化时清除
3. ~~onScrollEnd~~（从未调用）

### 为什么"看起来没问题"

`isScrollStateFresh()` 有 300ms TTL，所以过期后即使 `isScrolling == true`
也不会触发拦截 —— 行为上「自愈」了。

### 风险

这是**隐式依赖 TTL 兜底**，不是显式状态机：
- 若 TTL 被调大 → 拦截窗口变长
- 若有人误删 TTL 判断 → `isScrolling` 永久 true → **导航全部被吞（读屏"死机"）**

### 修复

1. `moveFocusInternal` 改为**显式状态机**：TTL 过期即主动清除标志
   ```kotlin
   if (isScrolling && !isScrollStateFresh()) {
       isScrolling = false          // ← 显式收敛
   }
   ```
2. `AutoScrollManager` 新增 `onScrollSettled` 回调，滚动结束即通知服务
3. 服务绑定：`autoScroll.onScrollSettled = { focus.onScrollEnd() }`
