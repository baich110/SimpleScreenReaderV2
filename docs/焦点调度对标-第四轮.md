## 本轮修复（1 处）

### `resetOperationScope` 漏清第三项

天坦 `FocusFinder.clearCache()`（`w7/FocusFinder.java:188~193`）清**三样**：

```java
public final void clearCache() {
    f39023h.clear();   // p 判定缓存
    f39017b = null;    // 基准矩形
    HashSet hashSet = f39022g;
    AccessibilityNodeInfoUtils.recycleAll(hashSet);
    hashSet.clear();   // 已访问子节点集合
}
```

而它在 `M6/h.D()` 的 **26 条退出路径**上被调用（已 grep 确认 26 处）。

白茶 `resetOperationScope()` 原来只清基准，上一轮补了 `pCache`，
**本轮补上 `seenChildren`** —— 三样齐了。

## 发现的能力缺口（非 bug，需决策）

### `focusInputField` —— 白茶完全没有

**调用条件**（`M6/FocusProcessorForLogicalNavigation.java:645~650`）：
```java
boolean isType15 = NodeUtils.isType15(current);
int nodeType = EventUtils.getNodeType(current);
if (!isType15 || (nodeType == 15 && direction != 1) || traversalMode == 8) {
    // 不走
} else {
    if (focusInputField(current, direction)) { ...; return true; }
    // 否则取前一个兄弟继续
}
```
即：**当前节点是 type15（网格容器）** 且 **方向 == 1** 且 **遍历模式 != 8** 时，
先尝试聚焦输入框。

**实现**（`:525~550`）：
- 通用路径：`TextEditingState.f(editingState, node, direction, null, 4, null)`
- 微信特判（版本 > 2320）：自定义 filter 遍历 → `focusNode` → 标记 action

**为什么重要**：聊天类界面（微信/QQ）里，用户在消息区滑动到底部后，
天坦能直接跳到输入框 —— 这是高频操作路径。
白茶缺这一步，用户滑到底后需要额外操作才能进输入框。

**为什么本轮没实现**：
1. 它是**新增能力**，不是 bug 修复 —— 而当前目标是「查 bug 修 bug，地基优先」
2. 它依赖 `TextEditingState` 状态机（白茶只有极简版 `isEditingText`）
3. 微信特判部分涉及版本判断，需要真机验证才能确认行为

**建议**：等真机验证完当前这批修复后，作为独立一项实现。
