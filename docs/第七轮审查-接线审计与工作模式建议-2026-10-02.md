**但漏了一个环节：`NavigationMode.typeCode` → `strategyTypeCode()` → `Factory` 这条链路上，中间那个函数还在传旧值。**

### 为什么测试没抓到

## 二、本轮新发现的 Bug

### 🔴 BUG-1：粒度遍历事件读整段文本（`extractTraversedText` 未接线）

**现象**：用户切到「按字」导航，按「下一个字」，**念的是整段文本，不是当前那个字。**

**代码**（`AccessibilityEventHandler.kt:297`）：

```kotlin
AccessibilityEvent.TYPE_VIEW_TEXT_TRAVERSED_AT_MOVEMENT_GRANULARITY -> {
    val text = event.text?.joinToString("")?.trim().orEmpty()   // ★ 读整段
    if (text.isNotEmpty()) {
        log("粒度遍历: $text")
        speech.speak(text, interrupt = true)                     // ★ 念整段
    }
}
```

**问题**：`event.text` 是**整个节点的文本**，不是「当前粒度单元」。

**正确做法**：`GranularityMover.extractTraversedText()` 已经写好了 —— 它优先用事件文本，退化时用 `event.fromIndex` / `event.toIndex` 从节点文本里切片。**但它没有被接线。**

**修复**：

```kotlin
AccessibilityEvent.TYPE_VIEW_TEXT_TRAVERSED_AT_MOVEMENT_GRANULARITY -> {
    // ★ 改用 extractTraversedText —— 它会从 fromIndex/toIndex 切出当前粒度单元
    val text = GranularityMover.extractTraversedText(event)
    if (!text.isNullOrEmpty()) {
        log("粒度遍历: $text")
        speech.speak(text, interrupt = true)
    }
}
```

**这是个真 bug，影响 P0-2 的完整性** —— 粒度导航的「移动光标」修好了（走系统 API），但「朗读当前单元」没接上。

### 🔴 BUG-2：输入法上屏 API 是死代码（无外部入口）

**现状**：`ReaderAccessibilityService` 有两个公开方法：

```kotlin
fun commitImeCandidate(text: String): Boolean     // 1132 行
fun canCommitImeText(): Boolean = imeAdapter.canCommit()   // 1155 行
```

**但整个 App 里没有调用方，也没有对外入口：**

```
Manifest 里只有：
  - 1 个 service（无障碍服务）
  - 2 个 activity（MainActivity / TtsSettingsActivity）

没有：
  - AIDL 接口
  - BroadcastReceiver
  - ContentProvider
  - 第二个 Service
```

**天坦是怎么做的**（`net/tatans/soundback/TatansImeService.java`，457 行）：

```java
public final class TatansImeService extends Service {
    // AIDL 接口：net.tatans.soundback.ITatansImeConnection
    public static final class b extends d.a {     // d.a = AIDL Stub
        public boolean F(IBinder iBinder, int i9, String str) { ... }
        public int L(IBinder iBinder) { ... }
        public void M(IBinder iBinder, int, int, int, int) { ... }
        public boolean O(IBinder iBinder, List list) { ... }
        public void Q(IBinder iBinder, c cVar) { ... }
        public void U(IBinder iBinder, String str, int, int) { ... }
        // ... 十几个 AIDL 方法
    }
}
```

**天坦输入法通过 `bindService` 连到这个服务，调用 AIDL 方法让读屏播报候选词、上屏文本。**

**我们的 `commitImeCandidate` 定义在无障碍服务上，但无障碍服务是系统绑定的（`BIND_ACCESSIBILITY_SERVICE`），第三方 App 无法通过 `bindService` 拿到它的 Binder。**

**所以这两个方法是**永远调不到的死代码**。**

**修复方案（两个选择）：**

**方案 A：加独立的 IME 服务 + AIDL（照抄天坦）**

```kotlin
// ImeConnectionService.kt
class ImeConnectionService : Service() {
    private val binder = object : IImeConnection.Stub() {
        override fun commitCandidate(text: String): Boolean =
            ReaderAccessibilityService.instance?.commitImeCandidate(text) ?: false

        override fun canCommit(): Boolean =
            ReaderAccessibilityService.instance?.canCommitImeText() ?: false

        override fun speakCandidates(text: String) { ... }
    }

    override fun onBind(intent: Intent): IBinder = binder
}
```

```xml
<!-- AndroidManifest.xml -->
<service
    android:name=".core.ImeConnectionService"
    android:exported="true"
    android:permission="net.baicha.reader.permission.IME_CONNECTION">
    <intent-filter>
        <action android:name="net.baicha.reader.IME_CONNECTION" />
    </intent-filter>
</service>
```

**方案 B：暂时删掉这两个方法**

如果短期不做输入法对接，**留着死代码会误导**（看起来「输入法适配已完成」）。

**建议**：至少加注释说明「需要外部 IME 通过 AIDL 调用，当前无对接方」。

## 三、工作模式建议

**你现在的模式已经很成熟了，我只提三个可以改进的点：**

### ① 测试要覆盖「会暴露问题的输入」

**这次的 `strategy_type_code_follows_mode` 就是反例** —— 用了 `LIST_TRAVERSAL`（两值相等），所以没暴露 bug。

**建议**：写回归测试时，**优先选「两值不同」的输入**。

```kotlin
// ❌ 弱：两值相等，测不出问题
m.setMode(NavigationMode.LIST_TRAVERSAL)   // typeCode=16, traversalType=16
assertEquals(16, m.strategyTypeCode())

// ✅ 强：两值不同，能暴露问题
m.setMode(NavigationMode.WORDS)            // typeCode=2, traversalType=0
assertEquals(0, m.strategyTypeCode())
```

**判断方法**：写完测试问自己「如果我故意把实现改错，这条测试会失败吗？」

### ② 「定义了字段」≠「改了用法」

**P0-1 的教训**：你加了 `traversalType` 字段、改了枚举声明、加了 `usesTraversal` 属性、写了回归测试 —— **但取值函数还是旧的。**

**建议**：改完「数据模型」后，**顺着调用链走一遍**：

```
NavigationMode.traversalType (新字段)
    ↓ 谁读它？
strategyTypeCode()          ← 检查这里
    ↓ 谁读它？
ReaderAccessibilityService:823
    ↓ 传给谁？
FocusManager.moveFocus(strategyType=...)
    ↓ 传给谁？
TraversalStrategyFactory.create(strategyType=...)
    ↓ 怎么解释？
when (strategyType) { ... }
```

**你说的「接线审计」方法（方法名出现次数 ≤ 1）能查「有没有调用方」，但查不出「调用方传的是不是新字段」。**

**补充一个审计**：**新增字段后，检查「所有读取该字段的地方」和「所有应该读该字段的地方」。**

### ③ 死代码要及时处理

**`commitImeCandidate` / `canCommitImeText` / `focusActionCode` 这类「定义了但调不到」的代码，比没写更危险** —— 它让人以为功能已完成。

**建议**：加个 `@Unused` 注解或 TODO 注释，标明「待接线」或「需要外部入口」。
