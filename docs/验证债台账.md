## 给用户的验证清单（按风险排序，一次装机验完）

### 必须验（坏了等于功能不存在）

**① 粒度导航**（#1 + #9，两者要一起验）
- 切到「按字」导航 → 按下一个字 → **应只念一个字**，不是整段
- 切到「按字词」→ 应只念一个词
- 这是 P0-2 + BUG-1 的联合验收；BUG-1 若没修，会念整段

**② 跨窗口导航**（#2）
- 打开一个弹窗 → 按「窗口导航」→ 应能走进去
- 再按 → 应能走出来

**③ 输入法上屏**（#6）
- 调出输入法 → 双击候选词 → **应能上屏**
- 注意：当前**没有 AIDL 入口**，只能验「降级的节点点击路径」
  是否生效；官方 `commitText` 路径需要自家输入法配合才能验

### 应该验（坏了影响体验）

**④ 滚动定位**（#4）
- 长列表里切到「跳到顶部」→ 按导航 → 应直接到顶
- 「跳到底部」用 `Integer.MAX_VALUE` 让容器 clamp，**不同 App 行为可能不同**

**⑤ 网页元素导航**（#5）
- 浏览器里切到「链接」→ 导航 → 应能按 HTML 语义跳
- 切到「链接」时，语音应念「**网页链接**」而不是「链接」

**⑥ 窗口几何分类**（#7）
- 遍历应用内容时，**不应**滑到状态栏的时间/电量上
- 这条依赖几何容差（5px），HyperOS 的实际尺寸可能不同于我假设的

### 顺带验（低风险）

**⑦ 垂直遍历**（#3）
**⑧ 进度播报**（#8）— 调音量时听是否念「百分之XX」

## 第九轮更新：变异测试（检验测试本身是否有效）

按审查报告「建议 8」，对实现**故意注入错误**，确认测试会失败。
测试不失败 = 无效测试 = 假的安全感。

### 结果

| 变异 | 结果 |
|---|---|
| 导航码取值函数改回 `typeCode` | ✅ 2 条失败 |
| 粒度切片放宽长度校验 | ✅ 4 条失败 |
| 窗口容差取消 | ✅ 4 条失败 |
| 状态栏高度比例 5→2 | ✅ 3 条失败 |
| 进度越界夹紧改错 | ✅ 4 条失败 |
| 音高指数分母 50→100 | ✅ 3 条失败 |
| 导航标签「网页链接」退回通用 | ✅ 4 条失败 |
| **输入法 API 门槛 33→26** | ❌ **逃逸** → 已修 |
| **滚动去重判定失效** | ❌ **逃逸** → 已修 |

### 两处逃逸的共同形态

**逻辑内联在依赖 Android 对象的方法里 → JVM 构造不出该对象
→ 测试只能测到外围的空值检查，核心判定零覆盖。**

- 输入法：测试全传 `null` service，而 null 检查在版本检查**之前**短路
- 滚动去重：判定在 `handleScroll(event)` 里，而
  `AccessibilityEvent.obtain()` 在 JVM 返回 null

### 统一修法：把判定抽成纯函数

| 抽出 | 从 | 补测试 |
|---|---|---|
| `ScrollDedup.isDuplicate()` | `handleScroll(event)` | 8 条 |
| `NavigationStore.resolve()` | `load(context)` | 3 组 |
| `ImeTextCommitter.isApiSupported()` | 内联版本比较 | 2 条 |

抽 `ScrollDedup` 时还加固了一处真实缺陷：
「两个 key 都取不到」原来会判为重复 → 无 source 的滚动事件
（系统合成事件）被**全部吞掉**，用户滑半天没声音。
现改为放行 —— 宁可重复播报，也不静默丢失。

### 结论

测试数 525 → 539。重点不在数量，而在**找出了三条
「看起来有测试、实际测不到」的盲区**。

## S1 的详细说明（本轮）

### 为什么测试测不到核心场景

JVM 单测里 `AccessibilityNodeInfo` 是**空壳**：
`getChild()` / `getParent()` / `getBoundsInScreen()` 全部返回默认值。
**构造不出「会被 RecyclerView 回收的树」** ——
而这恰恰是 S1 要解决的核心场景。

所以本轮回合只测了「纯计算部分」（评分、权重、边界），
**真正的验收必须真机**。

### 真机验证清单（S1）

**怎么验**：
1. 打开微信 → 进入一个**长列表**（如联系人列表）
2. 用读屏滑到**列表中段**某个联系人（记下名字）
3. **息屏，再亮屏**
4. **预期**：焦点回到那个联系人
5. **失败表现**：焦点跳到列表顶部（修复前的行为）

**再验一次跨 App**：
1. 在 App A 里滑到某处
2. 切到 App B，再切回 App A
3. **预期**：焦点回到原位置附近

**还要验滚动回收**：
1. 长列表里滑到中段某处
2. 快速大幅滑动（触发 RecyclerView 回收）
3. 滑回原处
4. **预期**：焦点不错位到相邻项

### 失败时的判断依据

日志里会有：
- `恢复焦点：按路径找回成功` → 路径恢复生效
- `恢复焦点：路径未命中 → 取第一个` → 走了兜底（说明路径没匹配上）
- `恢复焦点：无路径记录 → 取第一个` → 采集环节没生效

**这三条日志能把「哪一环坏了」定位到具体位置** ——
这是本轮特意加的，因为 S1 的失败模式靠肉眼看不出来。

## A4 连续朗读的真机验证清单（本轮新增）

**测不到什么**：朗读是否真的连续（自动推进下一项）、
TTS 完成回调时序、估算时长是否贴合真人语速。

### 怎么验

**① 基本连续朗读**
1. 打开任意长列表（如设置页）
2. 焦点停在某一项
3. **3 指三击**（原绑「屏幕识别」，该功能未实现故改绑）
4. **预期**：自动逐项朗读下去，无需滑动
5. **失败表现**：只读一项就停 / 完全没反应

**② 打断**
1. 朗读进行中，**轻点屏幕** → 预期立即停止
2. 朗读进行中，**长按** → 预期立即停止
3. 朗读进行中，**触摸探索**（拖动手指）→ 预期立即停止

**③ 进度条豁免**
1. 在有进度条的页面（如播放器）启动连续朗读
2. **预期**：进度条自动更新**不会**打断朗读
3. **失败表现**：每走一格就断一次

**④ 结束**
1. 一直读到页面末尾
2. **预期**：播完成音 + 自动停止

**⑤ 估算时长是否合理**
- 若「长文本没读完就跳走」→ 调大 `PER_CHAR_MS`
- 若「短文本读完干等」→ 调小 `BASE_DELAY_MS`

### 失败判断依据（日志）

- `连续朗读：被事件打断（type=X）` → 打断生效，可据 type 判断是哪个事件
- `连续朗读：已读到末尾` → 正常结束
- `连续朗读：推进异常 xxx` → 推进出错

## 【重要】本轮发现的崩溃缺陷（已修，需真机复验）

**`gestureActions` 声明为 `lateinit` 却从未初始化**，
而它在 3 处被使用：
- `isMediaPlaying = { gestureActions.isMediaActive() }`
- `onMappedAction = { gestureActions.handleMappedGesture(id) }`
- `handleMediaGesture → gestureActions.handleMappedGesture(id)`

**首次手势就会抛 `UninitializedPropertyAccessException`，
整个无障碍服务崩溃 —— 用户彻底失去辅助。**

已实例化并注入。**真机复验**：按任意映射手势（如双指上滑滚动），
服务不应崩溃。

## A5 TTS 补全的真机验证清单（本轮新增）

**测不到什么**：系统设置变更是否真的送达（ContentObserver 是否触发）、
唤醒锁是否真的阻止休眠 —— 都需真机。

### 怎么验

**① 系统设置改语速**
1. 打开 设置 → 无障碍 → 文字转语音（或 TTS 输出）
2. 把语速从正常调到最快
3. **预期**：白茶立刻用新语速朗读，**无需重启服务**
4. **失败表现**：语速不变（说明 ContentObserver 没生效）

**② 系统设置改引擎**
1. 同上路径，换一个 TTS 引擎（如换成讯飞/Google）
2. **预期**：白茶切换到新引擎
3. **失败表现**：仍用旧引擎

**③ 唤醒锁**
1. 启动连续朗读（3 指三击），或读一段长文本
2. **预期**：朗读期间屏幕不自动熄灭
3. **预期**：读完最后一句后屏幕才熄灭（`ON_AFTER_RELEASE` 的延迟效果）
4. **失败表现**：读到一半熄屏 / 读完后屏幕立即黑（无延迟）

**④ 电池（引用计数正确性）**
1. 反复触发朗读 20 次左右
2. 检查 设置 → 电池 → 白茶读屏 的耗电
3. **失败表现**：待机耗电异常（说明唤醒锁未释放）
   —— 这是引用计数写错的典型症状

### 失败判断依据（日志）
- `TTS 设置监听：已注册` → 注册成功
- `TTS 设置变更：语速 → X` → 观察生效
- `唤醒锁：已获取` / `唤醒锁：已释放` → 计数正确
- `唤醒锁：释放失败 xxx` → 计数异常
