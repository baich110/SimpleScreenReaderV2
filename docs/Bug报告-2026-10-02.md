## 零、真机实测现象（用户原话）

1. **左右滑动浏览时，焦点在动，但朗读不触发。**
2. **有些时候焦点会丢失，找不到焦点。**
3. （此前）**只能抓到功能按钮焦点（导航栏、底部 tab），抓不到微信聊天列表等内容项。**
4. （此前）**一个按钮被拆成多个焦点，或焦点合成一个后读不出内容。**

## 一、P0 —— 直接导致「焦点动、不朗读」

### #1 `SpeechCompositor.compose()` 的可见性早退太激进

**文件**：`app/src/main/java/com/baicha/reader/core/SpeechCompositor.kt`
**位置**：`compose()` 方法开头

```kotlin
fun compose(...): String? {
    if (node == null) return null
    if (!isVisible(node)) return null      // ← 问题在这
    ...
}

private fun isVisible(node: AccessibilityNodeInfo): Boolean = try {
    node.isVisibleToUser
} catch (e: Throwable) {
    false
}
```

**问题**：
`isVisibleToUser` 在以下场景会返回 `false`，但节点其实已经设上焦点了：
- 滚动过程中（节点正在移出/移入屏幕）
- 动画进行中
- 部分 App 实现不规范（尤其是自绘 View、Compose UI、Flutter/RN 混合栈）

一旦返回 false，`compose()` 直接返回 `null` → 调用方 `speakNode()` 走兜底分支 → 很可能什么都不播。

**为什么是错的**：
按天坦的职责划分，**可见性判定是 `ShouldFocusNode`（`w7/C3678d.r()`）的职责**，不是合成器的职责。合成器只管「把节点转成可读文本」。焦点已经设上了，说明它已经通过了判定，合成器不该再判一次。

**建议修法**：
```kotlin
fun compose(...): String? {
    if (node == null) return null
    // 删除可见性早退；可见性由 ShouldFocusNode 负责
    ...
}
```
如果确实需要防御（比如节点已失效），改成只在取文本全部失败时返回 null，而不是开头早退。

### #2 `speakNode()` 在 text 和 role 都为 null 时静默返回

**文件**：`app/src/main/java/com/baicha/reader/core/ReaderAccessibilityService.kt`
**位置**：`speakNode()` 方法

```kotlin
private fun speakNode(node: AccessibilityNodeInfo?, tag: String) {
    if (node == null) return

    val hash = node.hashCode()
    val now = SystemClock.uptimeMillis()
    if (hash == lastSpokenHash && now - lastSpeakTime < 300) return

    val text = composeNode(node, includeRole = true) ?: run {
        val role = SpeechCompositor.roleName(NodeRoleHelper.roleOf(node), node)
        if (role != null) {
            lastSpokenHash = hash
            lastSpeakTime = now
            log("$tag: $role")
            speech.speak(role, interrupt = true)
            playFocusSound(node)
        } else {
            log("$tag: (无内容)")      // ← 什么都不播
        }
        return
    }
    ...
}
```

**问题**：
`SpeechCompositor.roleName()` 对以下角色**全部返回 null**（见 `roleName` 的 when 分支）：

| 角色 | 常量 | roleName 返回 |
|---|---|---|
| 17 | `ROLE_CHECKED_TEXT_VIEW` | `null` |
| 30 | `ROLE_SCROLL_VIEW` | `null` |
| 31 | `ROLE_HORIZONTAL_SCROLL_VIEW` | `null` |
| — | `ROLE_VIEW_GROUP` | `null` |
| 其他 | `else` 分支 | `null` |

所以当 `compose()` 返回 null（见 #1）**且**节点角色是上述之一时 → **完全静默**。

**这就是「焦点在动，朗读不触发」的直接原因。**

**建议修法**：
加兜底，别静默。参考天坦行为，至少有三种兜底可选：
```kotlin
} else {
    // 兜底 1：播类名（至少让用户知道焦点在哪）
    val cls = node.className?.toString()?.substringAfterLast('.') ?: "元素"
    // 兜底 2：播「无标签」
    // 兜底 3：播坐标位置（调试用）
    log("$tag: (无内容) → 兜底播报: $cls")
    speech.speak(cls, interrupt = true)
    playFocusSound(node)
}
```

### #3 `speakNode()` 的去重用内容 hash，会误吞

**文件**：`app/src/main/java/com/baicha/reader/core/ReaderAccessibilityService.kt`
**位置**：`speakNode()` 开头

```kotlin
val hash = node.hashCode()          // ← AccessibilityNodeInfo 的内容 hash
if (hash == lastSpokenHash && now - lastSpeakTime < 300) return
```

**问题**：
`AccessibilityNodeInfo.hashCode()` 是**基于内容**的（text / contentDescription / bounds / className 等参与计算），不是对象身份。

后果：
- 两个**内容相同**的节点（例如：都是空文本的图标按钮、列表里格式雷同的项）→ hash 相同 → **第二个被去重吞掉，不朗读**。
- 内容相同的**不同节点**（比如两个「确定」按钮）→ 只读第一个。

**这是「焦点在动，朗读不触发」的第二个原因。**

**建议修法**：
```kotlin
val hash = System.identityHashCode(node)   // 对象身份，与天坦 HashSet<o0.w> 语义一致
```

或者更稳：同时比较「身份 + 时间」：
```kotlin
if (node === lastSpokenNode && now - lastSpeakTime < 300) return
```

### #5 `ShouldFocusNode.r()` 的 `prevBounds` 永远传 null → 微信特判被架空

**文件**：`app/src/main/java/com/baicha/reader/core/ShouldFocusNode.kt`
**位置**：`shouldFocus()` 与 `r()`

```kotlin
fun shouldFocus(node: AccessibilityNodeInfo?): Boolean {
    if (node == null) return false
    val c = cache
    if (c != null) {
        return c.shouldFocus(node) { r(node, false, 0) }   // ← prevBounds 用默认值 null
    }
    return r(node, false, 0)                              // ← 同样是 null
}

private fun r(node, z9: Boolean, depth: Int, prevBounds: Rect? = null): Boolean {
    ...
    // ⑤ 同一节点重复处理 且 有子节点
    if (prevBounds != null && isSameBounds(node, prevBounds) && node.childCount > 0) {
        if (WECHAT == node.packageName?.toString()) {
            val text = node.text?.toString()
            if (text == "图像" || text == "浮窗") return true    // ← 永远执行不到
            if (!k(node)) return false
        } else {
            if (!k(node) || !i(node)) return false
        }
    }
    ...
}
```

**问题**：
`prevBounds` 只在 `hasChildContent()` 递归调用时传了 `parentBounds`，**顶层调用永远是 null** → 第 ⑤ 步**永远不执行** → 微信特判（`"图像"` / `"浮窗"`）完全失效。

**天坦原版语义**：
`f39008c` 是**静态字段**，存「上一次被 `r()` 处理的节点的边界」，跨调用生效。天坦用它检测「同一个节点被连续处理两次」（防止重复聚焦）。

当前实现把它降级成了「父节点边界」，语义完全不同。

**建议修法**（二选一）：
- **方案 A（对齐天坦）**：恢复静态字段语义
  ```kotlin
  private val lastProcessedBounds = Rect()
  private var hasLastBounds = false

  private fun r(node, z9, depth): Boolean {
      ...
      if (hasLastBounds && isSameBounds(node, lastProcessedBounds) && node.childCount > 0) {
          // 微信特判...
      }
      // 函数返回前更新
      node.getBoundsInScreen(lastProcessedBounds)
      hasLastBounds = true
      ...
  }
  ```
- **方案 B（清理死代码）**：如果确定不需要这个分支，直接删掉，别留着误导。

### #6 `FocusManager.ensureReachable()` 是空壳，算完不用

**文件**：`app/src/main/java/com/baicha/reader/core/FocusManager.kt`
**位置**：`moveFocus()` 第 ⑤ 步 + `ensureReachable()`

```kotlin
if (target != null && target != current) {
    // ★ ⑤ 可达性判定（天坦 p()）
    val reachable = ensureReachable(current, target, direction, strategyType, root)
    if (!reachable) {
        ReaderLog.d(TAG, "目标不可达 → 尝试父节点")   // ← 只打日志，什么都没做
    }
    return if (applyFocus(target)) target else null   // ← 照常聚焦 target
}
```

```kotlin
private fun ensureReachable(...): Boolean {
    if (ShouldFocusNode.shouldFocus(target)) return true
    val parent = target.parent ?: return false
    if (ShouldFocusNode.shouldFocus(parent)) {
        return true        // ← 返回 true 但没告诉调用方「应该聚焦 parent」
    }
    return false
}
```

**问题**：
天坦 `M6.h.p()` 是**真的会退到父节点再试**的 —— 目标不可达时，改聚焦它的父容器。这里算完了把结果丢掉，等于没实现。**这会导致「焦点丢失」（现象 #2）。**

**建议修法**：
让 `ensureReachable()` 返回**实际应该聚焦的节点**，而不是 Boolean：
```kotlin
private fun resolveReachable(target: AccessibilityNodeInfo): AccessibilityNodeInfo {
    if (ShouldFocusNode.shouldFocus(target)) return target
    val parent = target.parent ?: return target
    if (ShouldFocusNode.shouldFocus(parent)) return parent
    return target
}

// 调用处
val actual = resolveReachable(target)
return if (applyFocus(actual)) actual else null
```

### #13 `CachedTraversalStrategy.flatten()` 没去重

**文件**：`app/src/main/java/com/baicha/reader/core/TraversalStrategy.kt`
**位置**：`CachedTraversalStrategy.flatten()`

```kotlin
private fun flatten(node: AccessibilityNodeInfo, out: ArrayList<AccessibilityNodeInfo>, depth: Int) {
    if (depth > 40 || out.size >= MAX_FLATTEN) return
    if (filter(node)) {
        out.add(node)              // ← 没检查是否已加过

    val count = node.childCount

    if (added.containsKey(node)) return       // 去重
    added[node] = true
    if (filter(node)) out.add(node)
    ...
}
```
（`release()` 里记得 `added.clear()`）
