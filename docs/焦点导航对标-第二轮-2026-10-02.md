## 一、P0-1：导航码 ≠ 遍历器类型码（接错）

### 现象

**用户切换到某些导航模式，遍历行为完全不对：**

| 导航模式 | 用户期望 | 实际行为 |
|---|---|---|
| **「字词」** | 按词遍历 | **用了 `CachedTraversalStrategy`（缓存遍历器）** |
| **「控件」** | 只停在控件 | **用了 `GridTraversalStrategy`（网格遍历）** |
| **「垂直遍历」** | 垂直方向遍历 | **落到 default（普通遍历）** |

### 根因

**两个不同的概念被当成了一个：**

```
NavigationMode.typeCode        ← 天坦 X6/z.b 的「导航标识码」
TraversalStrategyFactory.TYPE_* ← 天坦 C1427v.h() 的「遍历器类型码」
```

**代码里的错误连接：**

```kotlin

    direction = dir,
    strategyType = navigation.strategyTypeCode(),   // ★ 传的是「导航码」
    filter = navigation.filter()
)
```

```kotlin
// NavigationMode.kt:241
fun strategyTypeCode(): Int = current.typeCode      // ★ 导航码冒充遍历器码
```

```kotlin

    TYPE_GRID, TYPE_ROW_COLUMN -> GridTraversalStrategy(root, filter)

    TYPE_CACHED -> CachedTraversalStrategy(root, filter)
```

### 完整冲突表

| 导航模式 | 天坦导航码 | Factory 解释 | 实际结果 |
|---|---|---|---|
| `DEFAULT` 默认 | 0 | `TYPE_DEFAULT` | ✅ 正确 |
| `CHARACTERS` 字符 | 1 | else | ⚠️ default（凑巧对） |
| **`WORDS` 字词** | **2** | **`TYPE_CACHED`** | ❌ **缓存遍历器** |
| `SENTENCE` 逐句 | 3 | else | ⚠️ default |
| `PARAGRAPHS` 段落 | 4 | else | ⚠️ default |
| `LINES` 逐行 | 5 | else | ⚠️ default |
| `LINKS` 链接 | 6 | else | ⚠️ default |
| `HEADINGS` 标题 | 7 | else | ⚠️ default |
| **`CONTROLS` 控件** | **8** | **`TYPE_GRID`** | ❌ **网格遍历** |
| `SCROLLABLE_WIDGET` | 12 | else | ⚠️ default |
| `LIST_TRAVERSAL` 列表 | 16 | `TYPE_LIST` | ✅ 凑巧对 |
| `ROW_AND_COLUMN` 行列 | 31 | `TYPE_ROW_COLUMN` | ✅ 凑巧对 |
| **`VERTICAL_TRAVERSAL` 垂直** | **17** | else | ❌ **应该是垂直遍历** |

**注意：`LIST_TRAVERSAL`(16) 和 `ROW_AND_COLUMN`(31) 是「凑巧对」——**
**它们对是因为天坦的导航码碰巧等于 Factory 的类型码，不是设计如此。**

**天坦把这两个概念**分开传递**：**

## 二、P0-2：粒度导航是空壳（没实现）

### 现象

**「按字/按词/按行」导航切换后，遍历行为没有任何变化。**

### 根因

**`applyGranularity()` 把切分后的片段又拼回去了：**

```kotlin
// SpeechCompositor.kt:378
private fun applyGranularity(text: String?, level: GranularityNavigator.Level): String? {
    if (text.isNullOrEmpty()) return text
    if (level == GranularityNavigator.Level.DEFAULT) return text

    val segments = GranularityNavigator.split(text, level)   // 切分
    if (segments.isEmpty()) return text
    return segments.joinToString(SEPARATOR)                  // ★ 又拼回去
}
```

**「按字导航」的实际效果 = 把每个字用分隔符拼起来朗读一遍。**
**这不是「移动到下一个字」，而是「重新读一遍整段，只是加了分隔符」。**

### 天坦/TalkBack 的真实做法：用系统原生粒度 API

**天坦（`X6/e.java:271`）：**

```java
bundleA.putInt("ACTION_ARGUMENT_MOVEMENT_GRANULARITY_INT", aVar.f9299c);
if (n.f10643d.d(wVar2, aVar)) {
    if (this.f10598h.f(wVar2, aVar, z9)) {
        return 1;
    }
} else if (AbstractC3675b0.c(wVar2, i9, bundleA)) {
    // ★ performAction(ACTION_NEXT_AT_MOVEMENT_GRANULARITY, bundle)
    AbstractC4354b.h("CursorGranularityManager",
        "granularity traversal handled by framework", new Object[0]);
    return 1;
}
```

**TalkBack（`CursorGranularityManager` + `GranularityIterator`）：**

```java
// CursorGranularity.java —— 35 种粒度
DEFAULT(1, 0),
CHARACTER(2, AccessibilityNodeInfoCompat.MOVEMENT_GRANULARITY_CHARACTER),
WORD(3, AccessibilityNodeInfoCompat.MOVEMENT_GRANULARITY_WORD),
LINE(4, AccessibilityNodeInfoCompat.MOVEMENT_GRANULARITY_LINE),
PARAGRAPH(5, AccessibilityNodeInfoCompat.MOVEMENT_GRANULARITY_PARAGRAPH),
// ... Web 专用 30 种
```

**核心差异：**

| | 我们的做法 | 天坦/TalkBack 的做法 |
|---|---|---|
| 机制 | 自己 `split()` 字符串 | `performAction(ACTION_NEXT_AT_MOVEMENT_GRANULARITY)` |
| 光标 | **不动** | **真的移动** |
| 依赖 | 无（纯字符串） | App 自己实现粒度移动 |
| 正确性 | ❌ 假动作 | ✅ 系统级 |

**为什么必须用系统 API：**

1. **光标位置由 App 维护** —— 我们 split 字符串，App 里的光标根本没动，用户按「按字下一个」时 App 不知道要动哪里
2. **App 可能自定义粒度** —— 比如代码编辑器按 token 移动，我们 split 不出来
3. **朗读与光标必须同步** —— 系统会发 `TYPE_VIEW_TEXT_TRAVERSED_AT_MOVEMENT_GRANULARITY` 事件，我们已经在监听（`ReaderAccessibilityService.kt:655`）但没发送动作

### 修复方案

```kotlin
/**
 * 粒度移动 —— 对应天坦 X6/e.java:271 + TalkBack CursorGranularityManager
 *
 * 【为什么必须用系统 API】
 *   光标位置由 App 维护。我们 split 字符串只是「读了一遍」，
 *   App 里的光标没动 —— 用户再按「按字下一个」时 App 不知道从哪开始。
 *
 *   系统 API 让 App 自己移动光标，并回发
 *   TYPE_VIEW_TEXT_TRAVERSED_AT_MOVEMENT_GRANULARITY 事件，
 *   我们从事件里读新光标位置的文本。
 */
object GranularityMover {

    /** 粒度 → 系统常量 */
    fun toSystemGranularity(level: GranularityNavigator.Level): Int = when (level) {
        GranularityNavigator.Level.CHARACTER ->
            AccessibilityNodeInfo.MOVEMENT_GRANULARITY_CHARACTER
        GranularityNavigator.Level.WORD ->
            AccessibilityNodeInfo.MOVEMENT_GRANULARITY_WORD
        GranularityNavigator.Level.LINE ->
            AccessibilityNodeInfo.MOVEMENT_GRANULARITY_LINE
        GranularityNavigator.Level.PARAGRAPH ->
            AccessibilityNodeInfo.MOVEMENT_GRANULARITY_PARAGRAPH
        else -> 0
    }

    /**
     * 移动粒度 —— 对应天坦 AbstractC3675b0.c(node, action, bundle)
     *
     * @param node 当前焦点节点（必须是可编辑或有文本的）
     * @param level 粒度
     * @param forward true = 下一个，false = 上一个
     * @return 是否成功（App 支持该粒度）
     */
    fun move(
        node: AccessibilityNodeInfo,
        level: GranularityNavigator.Level,
        forward: Boolean
    ): Boolean {
        val granularity = toSystemGranularity(level)
        if (granularity == 0) return false

        val action = if (forward) {
            AccessibilityNodeInfo.ACTION_NEXT_AT_MOVEMENT_GRANULARITY
        } else {
            AccessibilityNodeInfo.ACTION_PREVIOUS_AT_MOVEMENT_GRANULARITY
        }

        val bundle = Bundle().apply {
            putInt(
                AccessibilityNodeInfo.ACTION_ARGUMENT_MOVEMENT_GRANULARITY_INT,
                granularity
            )
            // 天坦：是否扩展选区
            putBoolean(
                AccessibilityNodeInfo.ACTION_ARGUMENT_EXTEND_SELECTION_BOOLEAN,
                false
            )
        }

        return try {
            node.performAction(action, bundle)
        } catch (e: Throwable) {
            ReaderLog.w("GranularityMover", "粒度移动失败: ${e.message}")
            false
        }
    }

    /**
     * 检查节点是否支持指定粒度 —— 对应天坦
     * `AbstractC3688i` 里的粒度支持检查
     */
    fun isSupported(node: AccessibilityNodeInfo, level: GranularityNavigator.Level): Boolean {
        val granularity = toSystemGranularity(level)
        if (granularity == 0) return false
        return try {
            node.actionList.any {
                it.id == AccessibilityNodeInfo.ACTION_NEXT_AT_MOVEMENT_GRANULARITY
            }
        } catch (e: Throwable) {
            false
        }
    }
}
```

**同时需要改 `GranularityNavigator`：**

```kotlin
    PARAGRAPH,      // ★ 新增（TalkBack 有，天坦也有）

```

**以及事件处理（已有监听，需补处理）：**

## 四、P1：与 TalkBack 的其他差距

### 🟠 P1-1：缺少「跳到顶部/底部」

**TalkBack 的 `NavigationAction`：**

```java
public static final int JUMP_TO_TOP = 2;
public static final int JUMP_TO_BOTTOM = 3;
```

**我们**：无。`GestureAction` 里没有对应项。

**天坦**：也没有（`grep 跳到` 零结果）。

**判断**：TalkBack 有，天坦没有 → **优先级中等**。但实现成本低（找树里第一个/最后一个可聚焦节点），建议加上。

### 🟠 P1-2：缺少 `ACTION_SCROLL_IN_DIRECTION`（API 23+）

**TalkBack 用它做「按方向滚动」。**

**我们**：`AutoScrollManager` 用的是 `ACTION_SCROLL_FORWARD/BACKWARD`（只有上下）。

**天坦**：有 `ACTION_SCROLL_TO_POSITION`（`o0/w.java:170`），但也没用 `SCROLL_IN_DIRECTION`。

**判断**：**优先级低**。`SCROLL_IN_DIRECTION` 需要 API 23+，且兼容性不如传统滚动。

### 🟠 P1-3：缺少 `ACTION_NEXT_HTML_ELEMENT`（Web 元素导航）

**天坦有**（`m6/TextEditingState.java:170`、`w7/AbstractC3693m.java:629`）：

```java
bundleB = j0.e.b(p5.p.a("ACTION_ARGUMENT_HTML_ELEMENT_STRING", str));
```

**TalkBack 有**（`WebInterfaceUtils.HTML_ELEMENT_MOVE_BY_*`，30+ 种 Web 粒度）。

**我们**：无。

**判断**：**优先级中等**。如果要在浏览器/WebView 里按标题/链接/表单导航，需要它。但**天坦也只用于文本编辑状态**，没做完整的 Web 导航。

```kotlin
fun granularityLevel(): GranularityNavigator.Level = when (current) {

```

**修法**：`Level` 加 `SENTENCE` / `PARAGRAPH`，`granularityLevel()` 补映射。

# 修复完成情况（第三轮，2026-10-02）

## P0-1 导航码与遍历器码混用 ✅ 已修复

**根因**：`NavigationMode.strategyTypeCode()` 直接返回导航码，
而导航码会撞上遍历器类型码：

| 导航 | 导航码 | 撞上的遍历器 |
|---|---|---|
| WORDS（字词） | 2 | `TYPE_CACHED`(2) |
| CONTROLS（控件） | 8 | `TYPE_GRID`(8) |

→ 3 个导航行为完全错误。

**依据**：天坦 `M6/h.D(i9=navigation, i10=traversalMode)` 是**两个独立参数**，
导航码和遍历方式从来不是一回事。

**修复**：枚举签名改为 `(label, typeCode, traversalType, kind, implemented)`，
两码彻底分离；新增 `TYPE_VERTICAL = 17` + `VerticalTraversalStrategy`。

## P0-2 粒度导航是空壳 ✅ 已修复

**根因**：`SpeechCompositor.applyGranularity()` 把文本 split 后再 join，
不移动光标、不改变朗读范围。功能和按钮都在，行为是假的。

**修复**：删除假动作 + 删除 `compose()` 的 `granularity` 参数，
粒度导航统一走系统光标 API：

```
NavigationMode(CHARACTERS/WORDS/...)
  → FocusManager.granularityMover
    → GranularityMover.move()  发 ACTION_*_AT_MOVEMENT_GRANULARITY
      → 系统移动文本光标
        → TYPE_VIEW_TEXT_SELECTION_CHANGED 回传
          → 服务朗读光标处文本
```

**顺带修复 P1-4**：粒度档位 4 → 6（补 SENTENCE / PARAGRAPH）。

## P0-3 未实现导航静默拒绝 ✅ 已修复

**修复**：`NavigationManager.onUnimplemented` 回调 + 服务播报；
`WINDOWS_NAVIGATION` 标记 `implemented=true`（`WindowTraversal` 已就绪）。
